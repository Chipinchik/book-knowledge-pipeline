# Воспроизведение и оценка исследования

Цель — сравнить программную нормализацию Rules и семантическую обработку Gemini на одном исходном снимке. Полнота, JSON-валидность и экспертная точность — разные показатели. Books to Scrape — учебный сайт; первые N книг каталога не являются репрезентативной выборкой рынка.

| Токены новых запросов | 10 478 |
| Fallback | 0 |
| Ошибки API / валидации по журналу | 0 / 0 |
| Локальные остановки | 5 событий run_request_limit |

Оба метода завершены. Подготовка к защите **не требует нового запуска Gemini**. Просмотр не является повторным инференсом. В архиве и оригинальном metrics.json сохранён прежний общий счётчик 5; UI отделяет локальные остановки от ошибок. Нельзя интерпретировать эти 5 событий как пять HTTP-сбоев: каждое имеет http_requests=0. Сохранённый журнал не даёт оснований придумывать сведения о внутренних попытках, которых в нём нет.

## Сценарий демонстрации

1. Запустите `python -m streamlit run app.py` в активированном окружении. Оставьте «Только просмотр».
2. На главной выберите сохранённое сравнение на 15 книгах, последовательно покажите Rules и Gemini.
3. В «Сбор данных» просмотрите исходные записи без нового сбора. В «Каталог книг» покажите поиск, фильтры, исходную категорию/описание, нормализованную тему, сохранённую аннотацию Gemini и ссылку на источник.
4. Откройте аналитику: распределения тем, цен GBP, рейтингов, полноту и пропуски. Скачайте нужные PNG. Пустая аннотация Rules ожидаема: этот метод её не создаёт.
5. Откройте сравнение. Программа проверяет общий хеш, experiment_id и набор ID книг. Укажите 13 новых ответов и 2 кеша; объясните 5 локальных остановок. Время включает работу с кешем, запросы, задержки, валидацию и checkpoints, но не означает чистое время вычисления модели и не включает ожидание между ручными продолжениями.
6. В экспорте скачайте CSV/JSON/SQLite, при необходимости откройте технические подробности. Исходные metrics.json и уточнённая статистика событий доступны раздельно.
7. Не объявляйте Accuracy/Macro-F1 или обоснованность измеренными, пока эксперт не заполнил проверенную разметку.

## Ручная оценка без изменения защищённых оригиналов

Сначала создайте **рабочую копию** результатов из проверенного ZIP в отдельном корне проекта либо скопируйте `outputs/experiments` и связанные `outputs/runs` в отдельную папку результатов. Сохраните оригинал и инвентарь. Для просмотра отдельной папки можно указать `BOOK_PIPELINE_OUTPUT` перед запуском Streamlit. Не выполняйте из такой копии новые API-запросы: она предназначена для оценки/демонстрации.

1. В рабочей копии используйте `rules/gold_labels.csv` как общий эталон для обоих методов. Для 15 книг целесообразно проверить всю выборку. Эталон не генерируется автоматически из ответов модели или category_raw.
2. По исходному описанию заполните topic_gold из фиксированного списка: Детектив, Фантастика, Наука, История, Бизнес, Искусство, Путешествия, Другое. Неуверенность опишите в notes. Проверенные метки подтвердите verified=yes (или да). Непроверенные оставьте пустыми.
3. Сохраните CSV UTF-8 с запятыми в **рабочую** папку Rules. Не меняйте id и заголовки. Скачивание/редактирование файла в Downloads само по себе не подключает разметку к программе.
4. Для каждого метода отдельно проверьте summary_reviews.csv и fact_reviews.csv: support=supported или unsupported только после сверки с источником. Не изменяйте исходный текст аннотации или fact_id. Остальные строки остаются not_evaluated.
5. Перезагрузите сравнение рабочей копии. Accuracy = правильные темы / проверенные записи. Macro-F1 усредняется по объединению истинных и предсказанных классов проверенной выборки. Без разметки значение отсутствует, а не равно 0%.
6. Метрики классификации характеризуют весь конвейер, включая fallback, если он есть. Указывайте размер проверенной выборки и число успешных Gemini. Валидный JSON не доказывает обоснованность фактов; аннотации тоже нуждаются в проверке.

Для сохранения evaluation.json в рабочей копии (замените путь на свой):

```bash
python -m coursework.cli evaluate --run review/outputs/runs/20261122T090140636739Z-2ca2bf
python -m coursework.cli evaluate --run review/outputs/runs/20261122T090200004373Z-ac7fbb --gold review/outputs/runs/20261122T090140636739Z-2ca2bf/rules/gold_labels.csv
```

## Новый отдельный опыт, только при необходимости

1. Нажмите «Новый эксперимент». Старый сохранится. Соберите 15–20 реальных книг (до 30 при достаточной квоте) или выберите уже сохранённый исходный набор. Для короткой проверки используйте назначение на 1–2 книги в дополнительных настройках.
2. В «Нормализация» зафиксируйте один снимок, N, модель и параметры. «Подготовить общий эксперимент» не вызывает API. Пара получает новый experiment_id, методы — отдельные run_id.
3. Выполните Rules. Затем выберите Gemini и проверьте фактическую бесплатную квоту своего проекта. Старый раскрытый ключ должен быть отозван/заменён. Бюджет проекта — 0; платный биллинг не подключать.
4. Время ожидания, задержки, общий бюджет запросов, скользящий суточный предел, повторы и выходные токены задаются в дополнительных настройках. GEMINI_FREE_TIER_CONFIRMED — лишь заявление, не проверка квоты. Задержка должна учитывать RPM/TPM; другие программы приложению неизвестны. Начальный бюджет 512 токенов не гарантирует полный JSON, размер можно выбрать до подготовки опыта.
5. Только после явного подтверждения нажмите «Запустить Gemini». Записываются исходный ответ и checkpoint. Кеш честно переиспользуется при совпадении входных данных/параметров; не очищайте его ради нового запроса.
6. При локальном лимите появятся X/N и причина остановки. Продолжайте существующий запуск после проверки квоты, при необходимости явно увеличив общий бюджет с учётом потраченного. Для повторения ранее отклонённого запроса есть отдельный флаг. Модель, снимок и размер ответа в продолжении не меняются.
7. При 429 дождитесь восстановления квоты, при 503 — доступности сервиса. При 404 модель недоступна: не подменяйте её внутри исследуемого опыта; подготовьте отдельный опыт с корректной моделью. Неопределённый сетевой исход автоматически не повторяется.
8. Успешные записи не отправляются повторно, fallback не считается успехом Gemini. Не смешивайте короткую проверку и основную статистику. Полное сравнение доступно после завершения обеих обработок.

## Что приложить к пояснительной записке

Происхождение/дату и способ отбора, общий SHA-256, experiment_id и оба run_id; модель, prompt_version и фиксированные параметры; N до/после дедупликации; HTTP-попытки, принятые новые ответы/кеш, ошибки и паузы отдельно, fallback, usage и время; диаграммы; ручные метрики только после проверки; примеры различий с URL.

Не суммируйте 15+15 как 30 исходных книг. Не делайте вывод о превосходстве метода только по заполненности. Сохранённые старые PNG не перезаписываются; актуальные диаграммы со скорректированной классификацией событий скачивайте из приложения в отдельную папку.

Резервная копия и перенос — README.md и reproducibility/README.md. Числовую сводку можно воспроизвести без сети командой `python reproducibility/rebuild.py`. Исторические архивы, синтетические fixtures и mock-тесты не являются результатами основного опыта.
